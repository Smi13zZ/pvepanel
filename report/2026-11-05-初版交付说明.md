## 一、做了什么

一个飞牛 fnOS 原生的 fpk 应用，七个只读页面，视觉体系直接沿用现有 fpk 应用：
同一套设计令牌（近黑/近白反色导航、10 px 圆角、扁平卡片无阴影）、同一组字重
（400/500/600）、同一套明暗主题切换与响应式断点。

| 页面 | 内容 |
|---|---|
| 总览 | 节点卡片（CPU/内存/负载/运行时长）、集群仲裁与 HA、告警汇总、资源曲线（五档时间窗）、存储水位 |
| 虚拟机 | VM/CT 混排、状态筛选、搜索、CPU/内存条形占用、运行时长、模板标记 |
| 存储 | 每个存储的用量环 + 可用容量 + 内容类型 + 共享标记 |
| 磁盘 | 物理盘型号容量、SMART 健康、**温度**、SSD 寿命；「未被任何备份覆盖」清单 |
| 任务 | 备份/迁移/启停记录与成败、订阅状态、系统服务健康 |
| 设置 | 地址与 Token、连接诊断、告警阈值、刷新节奏、运行日志 |

**告警覆盖 10 类**：节点离线、集群失去仲裁、存储水位、虚拟机无备份、备份任务失败、
磁盘 SMART 异常、磁盘温度超阈值、订阅即将到期、权限不足、Token 失效。

## 二、技术形态

```text
浏览器（飞牛桌面 iframe）
  ↓ /cgi/ThirdParty/fn-pvepanel/index.cgi/   ← fnOS 登录闸门在这一层
index.cgi（shell 反代垫片）
  ↓ curl 127.0.0.1:8899
pvepanel.py（纯标准库 HTTP 服务）
  ├── pveclient.py   连接池 + 401/403 分流 + 免认证指纹
  ├── collector.py   分层 TTL 采集 + 告警聚合 + 401 熔断
  └── store.py       配置与 Token（chmod 600）
  ↓ HTTPS 8006（CERT_NONE 应对自签）
Proxmox VE
```

**浏览器永远不接触 PVE 地址和 Token**，所有请求由本机服务转发——既没有 CORS 面，
Token 也不出设备。

后端零第三方依赖（纯 `http.server` + `urllib` + `ssl`），前端离线打包 Vue 3，
整个包 202 KB。

## 三、三个关键设计决策

这三条都来自对真实 PVE 的实测，改动时不能删。

### 1. 401 立即熔断（而不是加重试）

PVE 对**每一次**认证失败都压满 3 秒才回（源码 `AnyEvent.pm` 里 `$delay = 3 - elapsed`），
且 4xx 强制 `Connection: close`。放任轮询的话，8 个端点串行 = 24 秒，三节点集群 = 60 秒，
面板看起来就是死了。

面板的做法：**首个 401 中止整轮采集**，不重试、不拉剩下的端点，切到「Token 已失效」
状态并停止轮询。实测一次强制刷新正好 **3.0 秒**收尾，不随时间累积。

同时**保留最后一次成功数据**继续显示并标记为「已冻结」，而不是清空成 0——
巡检的人需要看到出事前的样子，更需要区分「真的没有告警」和「数据停了」。

![Token 失效时的冻结态](<07-auth-failed.png>)

### 2. 探活绝不打需要认证的端点

`/api2/json/version` 需要有效 Token，没配时每次探活白烧 3 秒。面板改用 `GET /`
（免认证、约 5 ms），顺带从页面里读出 PVE 版本和节点名——所以 **Token 还没填的时候，
首屏也能显示「PVE 在线 / 9.2.21 / Chin」**，不是一个空白页。

### 3. Token 掩码不会被当成新值写回

`GET /api/settings` 把 Token 换成字面量 `__SET__` 返回，写入路径两道防线：
服务端遇掩码或空串沿用旧值；前端只提交改动字段。少任何一道，用户改个阈值就会把
Token 写成 `__SET__`，且无法自动恢复。

## 五、还需要你提供什么

**只有一个必须项：一个只读的 PVE API Token。**

目前所有「认证后很快」的结论都是拿免认证端点做地板推出来的，`/disks/smart` 这类
要调 `smartctl` 的后端计算型端点真实成本还未知（Mock 里给的 268 ms 是估的）。

请在 PVE 上执行（`PVEAuditor` 就够，**必须授在 `/` 并 propagate**）：

```bash
pveum user add monitor@pve --comment "fnOS PVE panel (read-only)"
pveum acl modify / --users monitor@pve --roles PVEAuditor --propagate 1
pveum user token add monitor@pve dash --privsep 1 --comment "fnOS panel token"
pveum acl modify / --tokens "monitor@pve!dash" --roles PVEAuditor --propagate 1
```

拿到 Token 后，在面板「设置」页填进去即可——**不用重装，也不用给我明文**，我可以直接
在测试机上验证，或者你自己在浏览器里填。

> 只授在 `/nodes/<node>` 子树的话，`/cluster/status` 和 `disks/smart` 会直接 403
> （这两个端点查的是根路径权限）。面板会显示「权限不足，请确认授在 / 并开启 propagate」
> 而不是笼统的「连接失败」。

**另外三个可以顺手确认的（不阻塞）：**

1. **面板监听 `127.0.0.1` 是否可以接受？** 现在只走飞牛桌面入口的 CGI，那条路带
   fnOS 登录校验。要局域网其他设备直连的话，得另做一个面板密码——否则任何能访问
   该端口的人都能看到整个集群的只读数据。
2. **v1 就只读够不够？** 启停、快照、备份触发需要 `VM.PowerMgmt` 等写权限，
   按之前评估归到 v2。
3. **要不要直接装到生产机 `fnos-prod`？** 测试机上已经跑通了，装生产机需要你先同意。

## 六、已知限制

- **进程崩溃不自愈**：开机自启有（appcenter 启动时批量拉起），但 `kill -9` 之后没人
  拉起，状态停在 `start`，要到应用中心手点启动。
- **只读**：写操作全部未实现。
- **拿不到的三类数据**：CPU/主板温度、风扇转速、单物理网卡吞吐——PVE API 层没有，
  不是没做。
