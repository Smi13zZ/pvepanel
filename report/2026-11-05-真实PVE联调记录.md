## 过程中撞到的四个真问题

### 1. 面板把 PVE 版本读成了 7.0.0

根页面上有多个 `ver=` 参数：ExtJS 自己报 `ver=7.0.0`，`proxmoxlib.js` 才是真正的 PVE 版本。
原来的正则是「取第一个匹配」，在 PVE 8 上就报成 7.0.0。现在优先读 `proxmoxlib.js?ver=`，
兜底时把 `7.x` 排除掉。修完读到的就是 `8.4.21`。

### 2. Token 授了 PVEVMAdmin 还是 403

这是 `privsep=1` 的经典坑：**Token 的有效权限是「用户权限 ∩ Token 权限」**。
只给 Token 授 `/vms` 的 `PVEVMAdmin` 不够，**所属用户也必须授同样的**。两条都补上才通。

这条之前写在文档里，这次是真踩到了：

```bash
pveum acl modify /vms --tokens "monitor@pve!panel" --roles PVEVMAdmin --propagate 1
pveum acl modify /vms --users  "monitor@pve"       --roles PVEVMAdmin --propagate 1   # 少了这行就 403
```

### 3. 官方源在这里慢到不能用

`download.proxmox.com` 在测试环境里只有 ~20 KB/s，装到一半卡住。换成清华镜像后快 30 倍，
一次装完。这不是面板的问题，但值得记下来——如果你在国内自己装 PVE，直接用镜像源。

```bash
deb [signed-by=/etc/apt/trusted.gpg.d/proxmox-release-bookworm.gpg] \
  https://mirrors.tuna.tsinghua.edu.cn/proxmox/debian/pve bookworm pve-no-subscription
```

### 4. cloud image 的两个坑

- **没有 SSH host key**：cloud-init 正常会在首启生成，我把它禁用了，于是 sshd 起不来
  （日志里 `sshd: no hostkeys available -- exiting`）。离线 `ssh-keygen` 补上即可。
- **没有 `vmbr0`**：apt 装的 PVE 不会自动建桥，嵌套 VM 一开机就报 `bridge 'vmbr0' does not exist`。
  我把 demo VM 的网卡删掉绕过了——这台测试机的目的是验面板的启停路径，不是验 VM 自身联网。

## 需要你决定的

1. **这台测试 PVE 要不要留着？** 它占 3 GB 内存 / 40 GB 磁盘（实际用了约 1.5 GB）；
   留着可以随时验证面板改动，删掉的话一条 `virsh undefine --remove-all-storage` 就清干净。
2. **生产 PVE（192.168.1.3）的 Token 还是没给我。** 上面这些是拿自建 PVE 验的，
   真机上的数据（PSI、SMART 温度、真实存储）还是拿不到。
3. 顺带提醒：如果生产 Token 也要启停，记得**用户和 Token 都要授 `/vms` 的 PVEVMAdmin**，只授一个会 403。
