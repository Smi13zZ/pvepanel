# PVEpanel 26.11.7 修正说明

2026-11-06 · 运行日志不该横向滚动

---

## 你说得对，但根因不是日志框，是每一条日志行

日志框本身（`max-height:240px; overflow:auto`）确实会滚，但真正撑出滚动条的是**行内的 flex 布局**。

`.logline` 是 `display:flex`，里面那个 `.m`（消息）是一个 flex 子元素。
flex 子元素的 `min-width` 默认是 `auto`，取的是**最长不可断单词的宽度**。
日志里有一行是：

```
[2026-11-06 03:00:27] 版本检查：接口查询失败（HTTP 403（GitHub 接口限流）），改走发布订阅源
```

这串中文里没有空格，对 CSS 来说就是一整个"单词"。于是 `.m` 的最小宽度 = 整行文字的宽度，
`flex:1 1 auto` 无法把它压下去，`.logline` 就比卡片宽，日志框长出横向滚动条。

**浏览器实测**（不是看代码猜的）：

```
viewport 500px | overflowing 13
div.logline cw=450 sw=504 ox=visible   × 12
div        cw=450 sw=504 ox=auto
```

`cw=450 sw=504` 就是 12 条日志行各自比容器宽 54px。

## 改法

```css
.logline { display: flex; min-width: 0; }
.logline .m {
  flex: 1 1 auto; min-width: 0;
  white-space: pre-wrap; overflow-wrap: anywhere; word-break: break-word;
}
.logbox { max-height: 240px; overflow-y: auto; overflow-x: hidden; }
```

三处缺一不可：

- `min-width: 0` 解除 flex 子元素按最长单词撑开的默认行为
- `overflow-wrap: anywhere` 允许超长 token 从中间断开（日志文本没有空格可断）
- `overflow-x: hidden` 让日志框只纵向滚，横向永不出现

## 顺手清掉的死代码

改的过程中发现 `.logline .t`（时间戳样式）是死代码——
HTML 里每条日志只有**一个** `.m` span，整个 `[时间戳] 消息` 是一整串字符串：

```html
<div class="logline"><span class="m">{{ l }}</span></div>
```

所以我原本写的"手机上时间戳单独一行"那条媒体查询根本不可能生效，只是看起来改了。
一并删掉，只留下真正起作用的三行换行规则。

## 这轮暴露的验证方法问题

我用 `--window-size` + `--dump-dom` 去量手机布局，但**这台 chromium 的 `--dump-dom` 忽略 `--window-size`**。
证据是三个不同尺寸全报 `window.innerWidth = 780`。也就是说前两次"手机端测量"其实是桌面测量。

改用"把溢出元素描红 + 把结果写进页面 + 截图"这套方法后才拿到真实数据。
这也解释了为什么第一版 `find_overflow.py` 只报了一个 `sr-only` —— 它是 780px 视口下的结果，
那个宽度下日志当然不会溢出。**测量工具本身错了，比不测更危险。**
