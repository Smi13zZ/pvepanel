## 1 / 2. PVE 9 与虚拟机验证

| 项 | 值 |

**为什么要两台**：PVE 8 和 9 的字段差异很大（PSI 压力、`memhost`、`decade` 只有 9 有），
只在一台上验，「字段缺失降级」这部分逻辑等于没测过。现在两台并存，一次改动两边都能看到。

![PVE 9 的虚拟机列表](<pve9-guests.png>)

### 启停验证结果

在 PVE 9 上逐条走：开 / 关 / 强制停止 / 重启，VM 和容器都覆盖。

| 操作 | 结果 |
|---|---|
| 启动停止的 VM | ✅ 返回 UPID，几秒后变 running |
| 停止运行的 VM | ✅ 同上 |
| 启动/停止容器 | ✅ `vzstart` / `vzstop` 任务都是 OK |
| 对已停的容器再停 | ✅ 正确报错「CT 400 not running」，不假装成功 |
| 非法操作名 | ✅ 本地拒绝，不发到 PVE |

### 顺手修掉的两个真 bug

**bug 1：`force=1` 没有绕过缓存。** 点刷新、执行启停后，页面读到的还是 8 秒 TTL 内的旧数据。
结果就是「点了没反应」——**这是最容易让人误判成 UI 问题的 bug**。现在强制刷新真的会清缓存。

**bug 2：连接池复用死 socket。** PVE 会主动关掉空闲的 keep-alive 连接，下一个请求就报
`Remote end closed connection without response`，看起来像 PVE 不稳定。现在识别到这种情况会换条新连接重试，
失败时清空整池。

## 3. 图标

**换掉了「白色 PVE 三字母」**，那是把名字写成字，不算设计。新版是**收窄的三层堆叠**：
深色底板上三条横杠，从上到下逐层收窄，顶层蓝色、下面两条白色（两档透明度做层次）。

![512px](<icon-preview-512.png>)

选它的理由是 **16px**：

| 候选 | 16px 下的问题 |
|---|---|
| 等宽三横杠 | 塌成汉堡菜单图标，最容易误读 |
| V 形 | 像下拉箭头/对勾，语义跑到 UI 控件上 |
| 字母 P | 只是把旧图标换了个说法 |
| 等距堆叠 / 立方体 / 节点拓扑 | 256 好看，16 全糊 |

关键在**收窄**：等宽会塌成汉堡，所以每层比上层窄，轮廓在 16px 下仍然独特。

![九档对照](<icon-sheet.png>)

三个技术点：
1. **斜切角由方程反解**——三条右端斜边落在同一条直线上（误差 0.000px），不是各自拍一个数
2. **小尺寸光学放大**（16px ×1.24），否则不到一个像素就糊了
3. **去掉字体依赖**——纯几何，不再有「找不到字体出空白图」的隐患

## 4. 手机端

审计先做了个**布局探针**（把面板放进精确尺寸的 iframe，逐元素量几何），而不是靠肉眼看截图。
这个选择是对的——它找出了一个肉眼很难确认的功能缺陷。

### 三个真问题

| # | 问题 | 严重度 |
|---|---|---|
| 1 | **虚拟机操作列被整列隐藏** —— 手机上能看状态，但不能启停 | 高（功能缺失） |
| 2 | 磁盘表 7 列 634px 塞进 380px，温度/寿命被卡片裁掉 | 高（信息丢失） |
| 3 | 顶栏标题被服务器下拉挤成半个字（360px 上「虚拟机」只剩 33px） | 中 |

**问题 1 值得单说**：原来是按列序一刀切（`nth-child(n+4)` 隐藏），
假设「第 4 列之后都不重要」，但操作列恰恰是第 8 列，于是被误杀。
手机上能看到哪台在跑、却动不了它，等于虚拟机页废了一半。现在改成按**列的用途**标记，操作列永远保留。

### 修完的样子

| | 修前 | 修后 |
|---|---|---|
| 虚拟机 | 只剩 3 列，无操作按钮 | VMID / 名称 / 状态 / **操作**（3 个按钮全在框内） |
| 磁盘 | 列被裁、表头错位 | 设备 / 容量 / 健康 / 温度，对齐 |
| 任务 | 结果列竖排成两行、行高翻倍 | 类型 / 对象 / 结果，紧凑 |

## 一个教训

这轮有次**协作事故**：我在改 HTML 的同时队友也在改 HTML 的同一区域，
我的写入把对方加的 `hide-xs` 类抹掉了，但 CSS 还留着 —— 于是规则成了死代码，
手机端一列都没隐藏。队友查了很久才定位到「交付的快照和验证的快照不是同一时刻」。

最后的修法是**把规则收敛到一个文件**（只用 CSS 的 `nth-child`，不依赖 HTML 里的类名），
任一侧被覆盖都不会静默失效。这比「下次注意」可靠。
