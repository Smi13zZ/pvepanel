## 1. 图标：九套都改了，文件名大小写是两回事

### 九套确实全都重新生成了

```
== app/ui/images ==            （九档 + icon_{0}）
  icon_16.png     (16, 16)    RGBA  四角 alpha = 0
  icon_24.png     (24, 24)    RGBA  四角 alpha = 3（24px 下圆角只占几个像素）
  icon_48.png     (48, 48)    RGBA  四角 alpha = 0
  icon_64.png     (64, 64)    RGBA  四角 alpha = 0
  icon_72.png     (72, 72)    RGBA  四角 alpha = 0
  icon_96.png     (96, 96)    RGBA  四角 alpha = 0
  icon_128.png    (128, 128)  RGBA  四角 alpha = 0
  icon_256.png    (256, 256)  RGBA  四角 alpha = 0
  icon_512.png    (512, 512)  RGBA  四角 alpha = 0
  icon_{0}.png    (512, 512)  RGBA  四角 alpha = 0
```

这十个文件 mtime 全是同一次生成（10:19），都是 RGBA。24px 那个四角 alpha 是 3 而不是 0，
是因为 24px 上圆角半径只有 5 像素，抗锯齿边缘落在角上——这是对的，不是漏改。

### 但外层那两个必须大写，这个改不了

根目录下的 `ICON.PNG` / `ICON_256.PNG` 是打包工具要求的大写文件名。我**实测过**改成小写会怎样：

```
$ mv ICON.PNG icon.png; mv ICON_256.PNG icon_256.png
$ fnpack build
Verifying files...
Packing failed. Required file ICON.PNG is missing
no fpk produced - packing genuinely failed
```

改回大写就正常：

```
$ mv icon.png ICON.PNG; mv icon_256.png ICON_256.PNG
$ fnpack build
Packing in progress...
Packing successfully.
```

而且我在 `fnpack` 二进制里找到了这两个字符串字面量：

```
$ grep -aoE 'ICON[A-Za-z0-9_.]*' /usr/local/bin/fnpack
ICON_256.PNG...
ICON.PNG...
```

所以职责是这样分的：

- **外层 `ICON.PNG` / `ICON_256.PNG`**：打包工具的固定约定，大写，改不了
- **`app/ui/images/` 下九档**：应用中心按密度取 `icon_{0}.png`，全小写，已符合

"名字要小写"这条我记下的是 `app/ui/images` 那一层——那里现在是全小写。

## 2. 手机端：取消隐藏，全部列 + 横向滑动

上一版我在手机上隐藏了 CPU、内存、运行时长、类型，这个判断错了。
列表也是"这台虚拟机占多少 CPU"要查的地方，少一半列等于答非所问。

现在三张表都恢复全部列，超宽时横向滑动，底部保留滑动提示。

**验证方式**：光看 CSS 说"没隐藏"不够——我用浏览器实测了渲染结果：

```
guests  cols=8 hidden=0  wrapper=754 content=976 scrolls=True
        VMID | 名称 | 状态 | CPU | 内存 | 运行时长 | 类型 | 操作
tasks   cols=6 hidden=0  wrapper=754 content=754 scrolls=False
        类型 | 对象 | 结果 | 开始 | 耗时 | 节点
disks   cols=7 hidden=0  wrapper=754 content=876 scrolls=True
        设备 | 型号 | 容量 | 类型 | 健康 | 温度 | 寿命
```

`hidden=0` 表示没有任何一列被 display:none。虚拟机表和磁盘表内容比容器宽，可滑动；
任务表 6 列 754px 正好放得下，不需要滑——这是正常情况，不是失败。

## 验证过程中修的两个测量工具

这轮最花时间的不是改代码，是**验证方法本身是错的**。

1. **`probe_cols.py` 用 `--window-size` 模拟手机宽度，但这个参数在这台 chromium 上无效**。
   三种尺寸全报 `780x437`，也就是说"手机测量"其实是桌面的测量，只是我以为是手机的。
   直接跑出来的第一版结果是错的。发现方法：写了个只输出 `window.innerWidth` 的最小页面去量。
   现在的断言改成基于"内容比容器宽时是否可滚"，不再依赖窗口尺寸。

2. **`shot.py` 的子串匹配 `loading`**（上一轮修的）：日志里有 `downloading`，
   导致渲染完的页面被误报"还在加载"。误报比没有检查更糟。
