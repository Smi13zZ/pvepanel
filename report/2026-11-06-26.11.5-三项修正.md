## 1. 应用图标四角变黑

**你看到的现象**：应用中心里 PVE 图标的四个角有黑色楔形，像没做圆角。

**根因**：生成图标时 `ICON.PNG` 与 `ICON_256.PNG` 被 `.convert("RGB")` 转成了 RGB。
这两个文件是靠 **alpha 通道**表达圆角的——转成 RGB 后透明像素被压成黑色，四个角就变成了黑块。
`app/ui/images/` 下的九档图标是 RGBA，所以一直是好的，只有这两个例外。

改前 / 改后的像素实测：

```
改前  ICON.PNG (64,64) RGB    四角 = (0,0,0,255)      <- 黑
改后  ICON.PNG (64,64) RGBA   四角 = (0,0,0,0)        <- 透明
改后  ICON_256.PNG    RGBA    四角 = (0,0,0,0)
```

打包产物本身也验过（不是只看源文件）：从 fpk 里解出这两个文件，确认仍是 RGBA、四角 alpha = 0、
边缘中点是白色。

![图标检查](<D:\Workspace\DeepSeek Harness\pve-panel\image\icon-check.png>)

深色背景上按应用中心的画法渲染，圆角正常；右侧是 16/24/48/64/128 各档。

## 2. 资源曲线刻度

**你提的两点**：首刻度不要顶头、时间日期要和刻度居中对齐。

**原来的问题**：刻度锚在日历边界上，于是第一个刻度贴死在绘图区左沿（标签有一半落在网格外），
最后一个也贴着右沿；而且首末两段的间距是"窗口切到哪算哪"，和中间的格子对不上。

**现在的做法**：刻度按绘图区宽度**均匀分段**，两端各留 22px 等宽空白，所以每个格子间距相同。
每个时间标签都 `textAlign = "center"` 画在自己的刻度线上——这是轴能读的前提。

刻度数量按可用宽度和**标签自身分辨率**共同决定：7 天的窗口最多只能显示 7 个不同日期，
要 8 个就必然有一个重复。所以加了一层上限，并额外抑制连续重复的标签
（先出现的是 `11-04 11-04` 这种，被这层挡掉了）。

几何实测（15 种宽度 × 档位组合，标签零重复、两端留白相等）：

```
W=900  hour   n=10  leftPad=22 rightPad=22  02:00 02:06 02:13 02:19 02:25 02:32 02:38 02:44 02:51 02:57
W=900  week   n=7   10-30 10-31 11-01 11-02 11-03 11-04 11-05
W=900  year   n=10  2025-11 2025-12 2026-01 2026-03 ... 2026-09 2026-10
W=340  week   n=4   10-30 11-01 11-03 11-05
```

## 3. 手机端操作列占掉半屏

**你说得对，之前那个做法是错的。** 我把操作列固定在右侧，想的是"按钮要能点到"，
结果 390px 的屏上三个按钮吃掉半行，除了按钮什么都读不到——
为了保留一个不该保留的东西，牺牲了整页的可读性。

**现在改成精简列**，跟桌面端用同一张表、靠 CSS 隐藏次要列：

| 表 | 手机保留 | 手机隐藏 |
|---|---|---|
| 虚拟机 | VMID / 名称 / 状态 / 操作 | CPU / 内存 / 运行时长 / 类型 |
| 磁盘 | 设备 / 容量 / 健康 / 温度 | 型号 / 类型 / 寿命 |
| 任务 | 类型 / 对象 / 结果 | 开始 / 耗时 / 节点 |

判据是"手机上真正要看什么"：虚拟机要知道是哪台、在不在跑、能不能动；
CPU/内存是概览页的活儿。磁盘要回答"这块盘是不是快坏了"。
任务要回答"什么失败了、失败在哪个对象上"。

**顺带修掉一个自相矛盾**：表格现在不滚动了，但底部还留着「表格可左右滑动查看更多列」。
这条提示改成只在表格确实会溢出的窗口宽度（641–1280px）下出现，桌面端和手机端都不再显示。

## 过程中顺手修的两处

1. **`shot.py` 的"页面还在加载"误报**：它用子串匹配 `loading`，
   而设置页会渲染面板自己的运行日志，日志里有 `downloading` 这一行（我上次更新测试留下的）。
   一个正常渲染完的页面被报成"还没加载好"。改成词边界匹配。
   误报比没有检查更糟——它会训练人忽略结果。

2. **`verify_v4.py` 硬编码版本号**：脚本里写死 `== "26.11.4"`，版本一升就假失败。
   改成从 `/api/health` 读实际版本再比对。
