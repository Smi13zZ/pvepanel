## 1. 中英文切换

侧栏底部第二个按钮，中文 ↔ English 即时切换，不用刷新。

257 个字符串全部双语，并且**有一致性约束**：中英两份键集合必须完全相同（我加了个校验，
缺一个键就会失败）。告警文案也是双语的——服务端下发的是事件键和数字，句子在前端拼，
所以切语言时告警不需要重新拉数据。

语言随设置保存，下次打开还是上次那个。

## 2 / 3. 图标与名称

应用名改为 **PVEpanel**：manifest 的 `display_name`、桌面入口 `app/ui/config` 的 `title`、
HTML 的 `<title>`、侧栏版本行全部改到。

图标重绘为黑底白字 **PVE**，三字母用等宽间距排布，右下角一个绿点（和面板里「已连接」
同一个色值，让图标和界面读起来是一个产品）。

字母用真字体渲染而不是手绘矩形——手绘的字形在 16px 下会糊成色块。生成脚本会按目标
尺寸逐级缩字重直到塞进安全区，**找不到字体直接报错**而不是默默出一张空白图。

主题按钮的三个图标现在是：显示器（跟随系统）/ 太阳（浅色）/ 月亮（深色）。
之前「跟随系统」是个半圆，和主题切换本身的语义容易混。

## 4. 磁盘与存储图标

这两个页面原来共用同一个盘片图形，在 18px 下几乎一样。现在：

- **磁盘** = 两个横向盘位叠在一起（机架里插着两块盘）
- **存储** = 数据库圆柱（容量池）

侧栏、卡片标题、页面标题三处一起换了，不是只改侧栏。

## 5. 多服务器

设置 → 服务器里可以添加任意多台 PVE，顶栏下拉切换当前查看的那一台。

**总览、虚拟机、存储、磁盘、任务全部只针对当前服务器**——不会把两台机器的数字
混成一张图，这也是你要的第 6 点。

服务端每台服务器有独立的缓存、连接池和认证状态，所以一台 Token 失效不会拖累另一台。

**老配置会自动迁移**：26.11.0 的 `config.json` 地址和 `token.json` 里的 Token 会迁成第一条
服务器记录，升级不用重填 Token。

## 6. 总览重排

CPU / 内存 / 负载拆成三张独立的卡片，每张都有自己的进度条和阈值着色：

- **CPU**：占用率 + 核心数 + 型号
- **内存**：占用率 + 已用/总量（加上 available 兜底）
- **负载**：1 分钟值 / 核心数 + 三档原始数字

负载卡按「核数归一」着色——`0.85` 表示 1 分钟负载到了核数的 85%，而不是一个固定的绝对值，
因为 32 核跑 8 个小时负载和 4 核跑 8 个小时负载完全是两回事。

## 7. 虚拟机启停

虚拟机页每行右侧三个按钮，按状态切换：

| 状态 | 可用操作 |
|---|---|
| 运行中 | 重启 / 关机 / 强制停止（红色） |
| 已停止 | 开机 |

强制停止会额外弹一句「相当于拔电源，可能丢失数据」。所有操作都有二次确认，
确认后才发请求，成功后自动刷新状态。

![虚拟机](<v2-guests.png>)

> **权限提醒**：这是面板唯一会写 PVE 的地方，需要 `VM.PowerMgmt`。`PVEAuditor` 是纯只读，
> **不含这个权限**。两种做法：换成 `PVEVMAdmin`，或者单独补一条——
>
> ```bash
> pveum acl modify /vms --tokens "monitor@pve!dash" --roles PVEVMAdmin --propagate 1
> ```
>
> 没有权限时按钮不会消失，点了会明确提示「权限不足：需要在 PVE 上给该 Token 授予 VM.PowerMgmt」，
> 比隐藏按钮好排查。

## 8. 通知推送 + 我推荐的告警项

### 九种通道

Bark / Server 酱 / PushPlus / WxPusher / Telegram / 企业微信机器人 / 钉钉机器人 /
Slack / 自定义 Webhook。每种通道的字段表由后端下发，前端零硬编码——加通道只改后端一个文件。

### 推荐的 12 类事件（都已实现，可逐条开关）

| 事件 | 默认 | 为什么推荐 |
|---|---|---|
| 节点离线 | ✅ | 最基础，也是最先该知道的 |
| 存储将满 | ✅ | 到 100% 会写失败、虚拟机可能挂起，提前告警才有意义 |
| 磁盘温度高 | ✅ | 硬盘临死前的直接信号，而且比 SMART 更早 |
| 磁盘健康异常 | ✅ | SMART 自检没过，通常意味着该换盘了 |
| 备份失败 | ✅ | 备份失效往往几周后才被发现，那时已经晚了 |
| 虚拟机无备份 | ✅ | **最容易被忽略的一条**：备份任务每天跑，但有些机器根本没被任何任务覆盖 |
| 负载偏高 | ✅ | 按核数归一，避免 32 核和 4 核用同一个阈值 |
| 内存紧张 | ✅ | 比 OOM 更早一步 |
| 订阅到期 | ✅ | 到期后没有官方源，升级会踩坑 |
| Token 失效 | ✅ | 面板自己瞎了要能告诉你 |
| 面板有新版本 | ✅ | 面板自身可升级 |
| 虚拟机意外停止 | ⬜ 默认关 | 需要状态跟踪，误报率取决于你的用法，所以留给用户自己开 |

### 三条设计约束

1. **推送判据 = 页面上的告警**。不会出现「页面红了但没推送」或反过来——因为两者读的是同一份数据。
2. **重复抑制**。每个事件带冷却（存储 6 小时、负载 30 分钟、订阅 24 小时……），一条 91% 的存储告警不会每 10 秒推一次。
3. **不阻塞页面**。推送在独立线程里发，webhook 慢或挂掉都不影响刷新。

![通知设置](<v2-notify.png>)

### 实测

起了一个本地 sink 服务，走完整链路：

```text
SINK /FAKEKEY {"title": "[PVEpanel] 存储将满",
              "body": "Chin · 2026-11-05 20:34\nChin/zfs-pool 已用 91%"}
第二次强制刷新：total posts = 1   ← 冷却生效，没有重复推送
```

钉钉加签也在队友的测试里验过：收到的 timestamp/sign 用同一算法独立重算，一致。

### 自更新

服务端每 60 秒查第一次、之后每小时一次，与浏览器是否开着无关；设置页可手动「立即检查」。
900 秒成功缓存 + 60 秒失败冷却，403 限流时自动退到不吃配额的 atom / expanded_assets。
仓库还没建，所以现在显示「还没有发布版本」——**不会误报成「已是最新」**。

## 还需要你确认的

**一个必须的**：只读 Token（`PVEAuditor`）。如果要试虚拟机启停，需要再补 `PVEVMAdmin` 或
单独授 `/vms` 的 `VM.PowerMgmt`。

**三个不阻塞的**：

1. 面板仍只监听 `127.0.0.1`（只走飞牛桌面入口）。要局域网直连得另做面板密码。
2. 通知推送要在你手机上配一个通道才有用，现在通道列表是空的。
3. 仓库 `Smi13zZ/pvepanel` 还没建，自更新现在只能显示「还没有发布版本」。
