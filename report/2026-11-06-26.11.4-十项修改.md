## 一、先说要紧的：一键更新的完整链路已经在真机上跑通了

不是"写完了能编译"，是**真的把一个正在运行的面板升级掉了**。

在 `fnos-test` 上起了一个假的 GitHub 发布服务（返回 v26.11.5 与一个真实的 .fpk 资产），
然后走面板自己的按钮路径：

     "script": ".../update/install.sh", "rollback": true, "pid": 1106554}

    === update to 26.11.5 finished ===

重启后：{"version": "26.11.5", "uptime": 10}，appcenter-cli status = running

**为什么这条要单独说**：写这段的两个模块（下载校验、脱离进程安装）都是队友并行做的，
他们各自的单测全绿，但只有把整条链路真跑一次才发现——
**安装脚本的模板不是 raw string，`printf '%s\n'` 里的转义换行被 Python 变成了真正的换行，
格式串的引号被截断。`sh -n` 语法检查照样通过，只在设备上真跑时才炸。**

这是"测过了"和"能用"之间的差距。测完之后我把测试用的假 GitHub 服务、26.11.5 的包、
update 目录、临时脚本全部清掉了，设备恢复成 26.11.4 正式运行状态。

## 二、逐条对应你提的十点

### 1. 图一：告警 → 警告

### 2. 图二：资源曲线的时间刻度

原来横轴只画"首 / 中 / 尾"三个采样点，看不出中间是什么密度。现在按**日历刻度**画：

| 档位 | 跨度 | 每格 |
|---|---|---|
| 时 | 最近 1 小时 | 10 分钟 |
| 日 | 最近 1 天 | 2 小时 |
| 周 | 最近 1 周 | 1 天 |
| 月 | 最近 1 月 | 5 天 |
| 年 | 最近 1 年 | 2 个月 |

刻度位置是走 `Date` 算的，不是按秒数硬加——跨月、跨 DST 都不会漂。
标签会相互碰撞时自动丢弃该刻度（连同它的网格线），不会出现半个字叠在一起。
曲线下方补了一行当前档位的说明，截图的时候一眼能看出这是哪一档。

实测数据跨度对得上（`tools/verify_v4.py` 里断言）：

```
tf=hour  span 1.0h      tf=day  span 24.0h
tf=week  span 167.5h    tf=month span 719.5h    tf=year span 8634.0h
```

### 3. 图三 / 图四：表格列宽固定 + 横向滚动 + 操作列左对齐

**根因**：原来是 `table-layout: auto`。自动布局下每列的宽度下限是它的 min-content，
所以一个长名字或长的设备路径就会把那一列撑宽、把别的列挤到 0——
表头文字重叠、操作按钮被挤出卡片，都是这么来的。

**改法**：三张表（虚拟机 / 磁盘 / 任务）全部改成 `table-layout: fixed`，
每列宽度写在 CSS 里，表格本身给一个 min-width，外面包一层 `.tscroll` 横向滚动。

列宽是按"表头一行放得下"的最窄值算的，表底标注了每个数字怎么来的，方便下次改：

```
tlist  1 VMID 88 | 2 名称 200 | 3 状态 100 | 4 CPU 88 | 5 内存 156
       6 运行时长 120 | 7 类型 84 | 8 操作 140            = 976
tdisk  ... = 876       ttasks ... = 716
```

**操作列左对齐**：原来是 `text-align: right` + `justify-content: flex-end`，
三个 28px 的按钮贴着列右沿，离「操作」表头老远。现在是左对齐，
按钮紧贴表头下方。

**手机端额外做了一件事**：光能横向滚动不够——「操作」是这一页的全部意义，
而它在最右边，手机上要滑过去才能点。所以窄屏下把操作列 `position: sticky; right: 0`
钉在右边缘，其余列在下面滑。360px 宽实测可用（截图 `m4-narrow-guests.png`）。

### 4. 图五：存储一横条一个占满一行

从两列网格改成 `grid-template-columns: minmax(0, 1fr)`，一个存储一行。
圆环在左，存储名 / 已用 / 可用 / 内容 / 节点 / 共享在右，宽屏下 kv 是四列一行排开，
窄屏自动降成两列。原来两列的时候，卡片的可用宽度只有一半，
96px 的圆环 + 标签值块要 ~430px，到窄窗口圆环直接被裁、kv 折成四行。

### 5. 图六 / 图七：任务页

- **页签**：任务页拆成「任务 / 订阅 / 系统服务」三个页签，跟图八一样可以在三者之间切换。
  之前是任务表 + 下面并排两张卡片，窄窗口会挤成一坨。
- **分页**：任务列表每页 10 条，底部有「上一页 / 第 N/M 页 / 下一页」+ 总数。
  列表长度变化时页号会自动收敛回范围内，不会停在空白页。
- **列宽**同上，六列固定宽度 + 横向滚动。

### 6. 图九：磁盘表的同一处毛病

和虚拟机表同一套改法：固定列宽、横向滚动、底部滑动提示。

### 7. 图十 → 图十一：服务器卡片化 + 当前项不涂绿

### 8. 图十二 / 图十三：更新分区重做

不只是样式，是整套逻辑重做。现在的结构：

- **当前版本 → 最新版本**的对照条（新版本用强调色）
- **状态条**：有更新 / 已最新 / 还没检查过，三种状态三种配色，右侧「检查更新」+「一键更新」
- **版本更新说明**：拉取 Release notes，13 行定高可滚（按整行算的高度，不会切半行字）
- **软件源 / 上次检查 / 发布时间 / 自动检查开关**
- **一键更新**：下载 → 校验 → 卸载 → 安装 → 重启，失败自动回滚

**进度条的两个细节**，都是踩过的：

1. **轮询必须排在阻塞请求之前**。下载是在 `POST /api/update/install` 里同步跑的，
   `await` 会一直挂到下载结束。等它返回才起轮询 = 全程零进度。
   正确顺序是先起 `pollUpdateProgress()`，再 `await installUpdate()`。
2. **进度只增不减**。服务端报的是瞬时快照，重试会让计数回退；
   前端用 watcher 记住峰值，进度条只往右走。

**安装期间的弹窗不关闭**：安装会卸载掉正在服务这个页面的进程，页面必然失联。
弹窗一直留到面板报出一个和开始前不同的版本号为止；失联期间显示「准备中…」
而不是假装有百分比，也不会因为接口连续失败就提前收场。

**已实测跑通**（见第一节）。

### 9. 参照做的一个维护分区

新增「维护」页签，四块：

1. **导出配置**：下载到本地。**不含 Token**——这个文件会离开设备，不能带集群凭据。
2. **导出到备份目录**：写到设备上的 `@appdata/fn-pvepanel/backups/`，**保留 Token**
   （否则恢复出来是个不能用的面板）。文件 0600，目录 0700。
3. **导入配置**：选文件 → 二次确认 → 覆盖。会拒绝外来文件（别的应用的备份）、
   损坏文件、格式版本不认识的，错误信息是可读的一句话而不是异常堆栈。
4. **自动备份**：开关 + 间隔（小时）+ 保留天数 + 上次成功 / 下次运行 / 上次错误。
   后台线程每 60 秒醒一次判断是否到期，循环体整体 try/except，线程不会死。
   列表里可以恢复或删除单个备份。

**两处故意和常规做法不一样，都是为了不出事**：

- **保留期只清理自动备份，不碰手动导出的**。按修改时间一刀切会把用户自己导出的也删了。
  读不出 `kind` 的文件也保留——更可能是损坏而不是可弃。
- **启动时不强制备份**。面板被频繁重启就会堆出一串几乎一样的快照。

### 过程中发现并修掉的三个真 bug

| 问题 | 现象 | 根因 |
|---|---|---|
| **导入配置会卡死** | 页面上点「导入配置」永远转圈 | `do_POST` 已经读过 body，import 路由又读一次；请求体是流，第二次读会一直等 socket |
| **客户端断连刷堆栈** | 日志里大段 `ConnectionAbortedError` | 只捕获了 `BrokenPipe`/`ConnectionReset`，没捕获 `ConnectionAborted` |
| **安装脚本能过语法检查却跑不了** | 单测全绿、`sh -n` 通过，设备上真跑才炸 | 脚本模板不是 raw string，`printf '%s\n'` 的转义换行被 Python 展开，格式串引号被截断 |

前两个是前端接线时发现的，第三个是**真机跑一遍**才发现的。
第一个尤其值得记一下：只跑单测永远不会碰到，因为它不在模块里，在 HTTP 层的调用顺序上。

### 数据不再消失

26.11.3 修的两个稳定性问题这版继续有效。这版的所有实测里快照始终 `errors: []`，
四个虚拟机、60 个曲线点、存储、磁盘、30 条任务、23 个系统服务、1 条警告全部正常返回。
